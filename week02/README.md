# 2주차 - 실습 환경 구축과 버전 관리 기초

## 이번 주에 한 일
리눅스 실습 환경(WSL2 + Ubuntu)을 만들고, 기본 명령어를 익힌 뒤, Git으로 버전을 기록해서 GitHub에 올렸다.

## 1. 가상화: 서버를 어떻게 운영할까
서버는 "무언가를 제공하는 쪽"을 뜻하고, 하드웨어를 가리킬 때도 소프트웨어를 가리킬 때도 있어서 문맥을 봐야 한다. 서버를 돌리는 방법은 세 가지로 비교했다.

| 방식 | 구조 | 특징 |
|---|---|---|
| 베어메탈 | 하드웨어 위에 OS 하나, 그 위에 프로그램 여러 개 | 구조가 단순하고 성능이 좋다. 프로그램 하나가 뚫리거나 자원을 몰아 쓰면 다른 프로그램도 영향을 받는다 |
| 하이퍼바이저(VM) | 가상 머신마다 게스트 OS와 커널을 가짐 | 격리가 강하지만 OS를 통째로 돌려서 무겁다 |
| 컨테이너 | 호스트 OS의 커널을 공유하고 공간만 격리 | 가볍고 빠르다. 호스트와 다른 종류의 OS는 못 돌린다 |

리눅스 컨테이너의 핵심 기술은 두 가지다. namespace는 프로세스·파일·네트워크를 서로 안 보이게 나누고, cgroups는 CPU나 메모리 사용량에 상한을 건다.

## 2. WSL2와 Ubuntu 설치
- 작업 관리자 > 성능 > CPU에서 가상화가 "사용"인지 먼저 확인했다. "사용 안 함"이면 BIOS에서 켜야 한다.
- 관리자 권한 파워셸에서 `wsl --install`로 설치하고, `wsl -l -v`로 버전이 2인지 확인했다.
- Ubuntu 첫 실행 때 사용자 이름과 비밀번호를 정했다.

## 3. 새로 배운 명령어
```bash
pwd                  # 지금 어느 디렉터리인지
ls -l / ls -a        # 권한까지 자세히 / 숨김 파일까지
mkdir, cd, rmdir     # 디렉터리 만들기, 이동, 빈 디렉터리 삭제
touch, cat, cp, mv, rm   # 파일 만들기, 보기, 복사, 이동(이름 변경), 삭제
chmod 755 파일       # 권한 변경 (r=4, w=2, x=1을 더한 숫자)
sudo apt update      # 패키지 목록 갱신
!!  /  !ls           # 직전 명령 재실행 / 가장 최근 ls로 시작한 명령 재실행
```
- `>`는 파일을 새로 덮어쓰고, `>>`는 뒤에 이어 붙인다.
- `rm -rf`는 되돌릴 수 없어서 조심해서 써야 한다.

권한은 `ls -l` 맨 앞 10글자로 읽는다. 첫 글자는 파일 종류, 그 뒤 세 글자씩 소유자, 그룹, 기타 사용자의 권한이다.

## 4. Git으로 버전 관리
```bash
git init                         # 이 디렉터리를 Git이 관리하게 함
git add 파일                     # 다음 커밋에 넣을 변경사항을 고름(스테이징)
git commit -m "first commit"     # 지금 상태를 하나의 버전으로 저장
git log --oneline                # 커밋 기록 확인
git switch -d <커밋 해시>        # 옛날 버전으로 이동해서 확인
git diff <해시1> <해시2>         # 두 버전의 차이 비교
git switch -c hi                 # 브랜치를 만들어 이동
```
`git add`는 파일을 저장하는 게 아니라 "이번 커밋에 포함할 것"을 고르는 단계라는 점이 헷갈렸다. 커밋은 게임의 세이브 포인트에 가깝다.

브랜치는 특정 커밋을 가리키는 이름이다. `hello.txt`를 main에서는 hello, hi 브랜치에서는 hi로 바꿔서 두 브랜치가 서로 다른 내용을 가질 수 있다는 걸 확인했다.

## 5. GitHub에 올리기
- `gh auth login`으로 로그인하고, `gh repo create`로 저장소를 만들면서 현재 폴더를 연결했다.
- 커밋만으로는 내 컴퓨터에만 있고, `git push`까지 해야 GitHub에 올라간다.
- 학교 PC에서는 작업이 끝나면 `gh auth logout`으로 꼭 로그아웃한다.
